The admin portal (`/admin`) is where platform admins run the install and platform auditors review it. People with either role get a **Workspace / Admin** switch at the top of the sidebar. Workspace is the ordinary experience; Admin shows only platform pages. Each side remembers the last page you visited in that browser tab.

<Callout title="No content access by default">
  Neither role can read a team's documents or anyone's conversations. The admin portal shows settings, metadata, usage and logs. A platform admin who needs to read a team's content opens an audited, time-limited [break-glass session](/docs/administration/break-glass), and the team's owners are told.
</Callout>

## Who can do what

| | Platform admin | Platform auditor |
|---|---|---|
| See every admin page | Yes | Yes, read-only (a "Read-only" badge in the top bar) |
| Change settings, create teams, manage models | Yes | No |
| Place legal holds, open break-glass sessions | Yes | No, but can see them |
| Read team content | Only under break-glass | Never |

The first platform admin is set by configuration ([First platform admin](/docs/self-hosting/kubernetes#5-the-first-platform-admin)). After that, admins grant platform roles under **People → Users**. The last active platform admin can't be demoted or suspended.

## Overview

The admin portal opens on **Overview**:

1. **Platform at a glance**: teams, people, agents, documents and answers, compared with the week before. A new install also gets a **Set up this install** checklist: add a connection and models, embedding profiles, moderation, and the first team.
2. **Needs attention**, beside **Features**. Needs attention lists what an admin should act on: domain requests, teams near or over budget, documents that failed to index, keys still on a previous pepper, connections, models and MCP servers whose [stored health](/docs/self-hosting/health) is failing ("1 connection is failing", each linking to its filtered list), and configuration warnings such as an empty crawl allowlist or no email. [Features](/docs/administration/features) lists each optional feature with its state and a link to where it's set (since v0.4.2 the switches are on [Settings](/docs/administration/settings), and the card reads everything in one request).
3. **Recent changes**: the last five audit entries, with **All logs**. Sign-ins, MCP tool calls and OAuth sign-ins are left out; the audit log has them.

## The sidebar

The admin sidebar has Overview and seven groups. Only Overview and the group of the page you're on open by themselves; other groups stay as you left them.

| Group | Pages |
|---|---|
| **People** | [Users, Teams](/docs/administration/people-and-teams), [SSO groups](/docs/administration/sso-groups) |
| **Content** | [Shared sources, Agents, Crawl domains](/docs/administration/content), [Parsing & OCR](/docs/administration/parsing-and-ocr) |
| **Models** | [Connections, Models](/docs/administration/models), [Embedding profiles](/docs/administration/embedding-profiles) (Profiles · Migrations), [MCP servers](/docs/administration/mcp-servers), [SystemOne](/docs/administration/systemone), [Reranking](/docs/administration/reranking) (since v0.4.2, always shown) |
| **Usage & spend** | [Analytics](/docs/administration/analytics-and-logs), [Costs](/docs/administration/costs), [Limits](/docs/administration/limits) |
| **Safety** | [Classifications](/docs/administration/classifications), [Moderation, Public access](/docs/administration/moderation-and-public-access) ([modes and reasoning](/docs/administration/moderation-modes)) |
| **Records** | [Logs](/docs/administration/analytics-and-logs#logs), [Retention](/docs/administration/retention) (Periods · Dry run · Runs · Legal holds), [Break-glass](/docs/administration/break-glass) |
| **Operations** | [Maintenance](/docs/administration/maintenance), [Settings](/docs/administration/settings) (since v0.4.2) |

The command palette (⌘K or Ctrl+K) finds admin pages, their tabs ("Costs › Settings", "Retention › Runs", "Limits › Ingestion") and places such as **Reranking settings**, **Features** and **Legal holds**; "time zone" or "currency" finds Settings, and "failing" or "health" offers **Failing models** and **Failing connections**. For platform staff it also finds teams, users, models, connections, embedding profiles and shared sources by name. It never returns another team's content.

Below 1100 px wide the sidebar starts as a rail of icons until you expand it (your choice is remembered); on a phone (below 600 px) it's a drawer opened from the top bar.

## Conventions

- **Records open as pages** over their list (a model, a connection, an audit entry, a hold), with a back link. Each can be linked to.
- **Changes are audited** with before and after values, and most admin writes use revision checks. Since v0.4.2, if another admin saved first (or changed the settings in another tab while you edit), your edits stay in the form: the fields you didn't touch take the other version, a notice lists what changed ("Description: now “…” (yours: “…”)"), and the save bar offers **Overwrite with mine** or **Discard mine and load theirs**. Before, the form reset to the other version.
- **Too many requests.** If your account makes more requests in a minute than the platform allows, a banner says "Too many requests: waiting before trying again" with a countdown and **Try again now**; if it happens before the app has loaded, a page says so with the same countdown. Nothing loops or replaces the app with a bare error (v0.4.2).
- **Moved pages keep their old addresses** as redirects, for example `/admin/legal-holds` and `/admin/profile-migrations`.
