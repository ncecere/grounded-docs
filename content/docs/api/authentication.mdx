## API keys

Programs authenticate with a team **API key**, sent as a bearer token:

```sh
curl -H "Authorization: Bearer rag_<id>_<secret>" https://grounded.example.org/v1/models
```

Keys are created in the app under **Team settings → API keys** ([API keys](/docs/using/owners/api-keys)); the secret is shown once. A key:

- belongs to **one team**, and reaches only that team's agents and knowledge bases;
- has **scopes**: `query` (chat and search), `ingest` (upload documents, start and cancel crawls, preview a site map, and read sources, documents and agents), `manage` (today the same calls as `ingest`), `mcp` (search and ask from AI tools over [`/mcp`](/docs/using/mcp); it grants nothing on the REST API: a key with only `mcp` gets `403 missing_scope` there);
- may be **restricted** to some knowledge bases and some agents. A knowledge-base restriction limits the knowledge bases it can search and the data sources and documents it can reach (only those the chosen knowledge bases use), and, when the key has no agent restriction, hides any agent whose draft or published configuration uses another knowledge base. An agent restriction limits which agents it may use and, since v0.6.1, the knowledge bases it reaches: only those the chosen agents' **published** versions answer from, followed if an agent is published again. With both restrictions, only the knowledge bases both allow. Before v0.6.1 an agent restriction did not limit knowledge bases;
- may **expire**;
- can never administer the platform.

| | Personal key | Service key |
|---|---|---|
| Acts as | You, within the team | The team |
| Scopes | By your role: members `query`, `mcp`; editors `query`, `ingest`, `mcp`; admins and owners all | Any (created by admins and owners) |
| Conversations | Stored for you; send `conversationId` to continue one | Stateless: send earlier turns in `history`; `conversationId` is refused |
| When the owner's role changes | Never above the owner's role now (made a plain member, `ingest` stops working) | Unchanged |
| When the owner leaves the team | Revoked | Keeps working |

A key with only the `query` scope, or a personal key whose owner is a plain member, sees an agent as a team member does: its profile and published version. `GET /v1/teams/{team}/agents` and the agent itself leave out the draft (instructions, knowledge bases and settings), the unpublished-changes flag and the publish problems. A key with `ingest` or `manage` still gets the draft.

Keys are stored only as HMAC digests. Per-key rate limits apply (300 queries per minute by default), as do the team's and the agent's limits. A revoked, expired or unknown key gets 401.

Some routes don't accept API keys at all: evaluations, the command palette search (`/v1/search`), and everything under `/v1/admin`. Whether team keys may call a knowledge base's `/retrieve` directly depends on its classification level's setting.

## MCP

The MCP server at `POST /mcp` takes an API key with the `mcp` scope as a bearer token, or, when a platform admin turns on the experimental [OAuth sign-in](/docs/self-hosting/mcp-server#oauth-sign-in-experimental), a short-lived access token (`gat_…`) issued to a signed-in person. Those tokens only work on `/mcp`: the REST API answers `401`. See [Connect AI tools](/docs/using/mcp).

## Publishable keys

A **publishable key** (`pk_…`) belongs to one public agent and can only start anonymous widget sessions from its allowed origins. It's meant to be embedded in web pages and isn't secret. See [Widget](/docs/using/editors/sharing#widget).

## Browser sessions

The web app uses a server-side session cookie. Scripts running in a signed-in browser can call the same `/v1` routes, but every write needs the session's CSRF token in the `X-CSRF-Token` header (read it from `GET /v1/me`) and a same-origin `Origin` header. Use API keys for programs instead.

Sessions last `SESSION_TTL` (12 hours by default). `GET /v1/auth/config` returns the sign-in methods and the install's identity without signing in.

## Anonymous access

Only public agents are reachable without credentials: their profiles, anonymous sessions and chat (`/v1/public/...`), `widget.js` and the embed page. Nothing else is available anonymously.
