---
title: Native chat API
description: Ask an agent with conversations, retrieval events and citation verdicts, streamed over Server-Sent Events.
---

`POST /v1/agents/{team}/{agent}/chat` is the API the web app's chat uses. Compared with the [OpenAI-compatible endpoint](/docs/api/openai-compatible), it keeps conversations for personal keys and sessions, and streams richer events: what the agent is doing before the first words, retrieval results, tool calls, moderation, and the citation check. It's part of the native API, which may change between minor releases before 1.0.

It needs a signed-in session or an API key with the `query` scope.

## The request

```json
{
  "message": "How do I request a transcript?",
  "conversationId": "…",
  "stream": true
}
```

| Field | Meaning |
|---|---|
| `message` | The question, 1–8,000 characters. |
| `conversationId` | Continue a conversation. Sessions and personal keys only. |
| `history` | Earlier turns (`{role, content}` with role `user` or `assistant`, up to 50), for stateless callers such as service keys. |
| `stream` | `true` (default) for Server-Sent Events; `false` for one JSON answer. |

Sessions and personal keys store the conversation; the first event tells you its ID. Service keys are stateless: send the history, and `conversationId` is refused.

## The event stream

Named events whose data is JSON, in this order:

| Event | When |
|---|---|
| `conversation` | First: the conversation's ID. |
| `status` | What the agent is doing before the answer's first words, once per step: `{"step": "rewriting"}` (turning a follow-up that depends on the conversation into a search query), `searching` ("search before every answer"), `checking` (SystemOne passage judging), `thinking` (since v0.4.0: the model is reasoning and its thinking isn't streamed, in checked-paragraph and buffered modes; sent once per stretch of reasoning, with no content), `answering` (the model is writing, until its first token). Since v0.3.0. Ignore steps you don't know. |
| `retrieval` | With "search before every answer": the passages found (numbered, with title, URL and snippet), and with passage judging the counts judged, kept and dropped. |
| `message_start` | The answer begins. Since v0.4.0 `mode` says how the answer is moderated: `stream_retract`, `stream_checked` (each `text_delta` is a checked paragraph) or `buffer`; absent without output moderation. `buffered: true` means the text arrives whole (buffer mode, or a [saved answer](/docs/using/editors/saved-answers), which has no `mode`): show it from its start. |
| `thinking_delta`, `text_delta`, `tool_call`, `retrieval`, `tool_result` | As they happen. `text_delta` carries raw model text. |
| `moderation` | Only when moderation replaced the question's answer or the answer with a notice. In `stream_checked` mode it's sent as soon as a paragraph fails: `retracted` when paragraphs were shown, `withheld` when none were; later text is dropped. |
| `message_end` | The final text (which replaces the deltas), `citations`, `usage`, `stopReason`, `refused`, `noContext` and `noContextReason`. For answers checked before release (buffered answers and JSON answers), also `claims` and `uncited`. Since v0.4.0 citations of passages carry `chunkId`. Since v0.4.1 `citationsPending: true` means the citations are being checked and `citations_checked` follows. |
| `citations_checked` | Only with SystemOne citation checks on and citations in the answer: follows `message_end` and replaces the citations, with `claims`, `uncited` and counts; in enforce mode, also the text. |
| `suggestions` | Since v0.4.1, after an answer with citations when the agent offers [follow-up suggestions](/docs/using/follow-up-suggestions): `{"messageId": "…", "suggestions": ["…"]}`, 1 to 3 questions of at most 150 characters. It follows `message_end` and `citations_checked`, and is sent only when there's at least one. |
| `error` | Only on failure, for example `model_unavailable`, `model_busy` or `incomplete_answer`. |
| `done` | Last. |

A citation of a tool's result (an agent's [MCP tool](/docs/administration/mcp-servers)) has `kind: "tool"`, `server`, `tool` and `truncated`, and nil document and source IDs; passages have no `kind`.

**The answer is complete** at `message_end`, or at `citations_checked` when `message_end` has `citationsPending: true`. Since v0.4.1 the stream may stay open after that for `suggestions`: show the answer as done, and keep reading until `done`. Closing the stream then (for example, because the person asked the next question) drops only the suggestions; the answer is already stored.

Steps that don't apply are skipped: a question that stands on its own isn't rewritten, an agent that searches only when needed sends just `answering` before its first turn, and without passage judging there's no `checking`. A blocked question gets `conversation`, `status`, `message_start`, `moderation` and `message_end`. A `: ping` comment is sent every 15 seconds. Closing the connection stops the answer; the partial answer is saved with the stop reason `aborted`.

In `message_end.text`, unknown `[n]` markers are removed, `[1, 2]` is written as `[1][2]`, and markers are removed entirely when the agent's citation mode is "No citations". `noContextReason` is `judged_out` (passage judging left nothing), `small_talk` or `out_of_scope` (the scope check) when those apply.

Errors before the stream starts (`agent_disabled`, `agent_policy_violation`, `rate_limited`, `quota_exceeded`, `budget_exhausted`, and `model_unavailable` when the agent's model is unusable) are plain HTTP errors, not events. The stream starts with the first `status` event, so a failure after it (`model_unavailable` or `model_busy` when the model is called) is an `error` event after `conversation`, and you still learn the conversation's ID. Before v0.3.0 these were HTTP `503` errors; clients that read the stream should handle `error` events. JSON answers (`stream: false`) and the [OpenAI-compatible endpoint](/docs/api/openai-compatible) are unchanged: the OpenAI-compatible stream sends no `status` and still starts with the answer.

## Conversations and feedback

| Route | Does |
|---|---|
| `GET /v1/conversations` | Your conversations (never anyone else's). |
| `GET /v1/conversations/{id}` | One, with its messages, citations and claims. Since v0.4.1 a message has `refused` when the answer was the agent's refusal (so a client can offer the starter questions again), and each stored tool call has `thinkingBefore`: how much of the message's thinking came before the call, in UTF-16 code units, to show the reasoning and the steps in the order they happened. Follow-up suggestions aren't stored. |
| `GET /v1/conversations/{id}/export` | Markdown or JSON, with citations. |
| `DELETE /v1/conversations/{id}` | Delete it (retention rules may keep the stored copy longer). |
| `POST /v1/messages/{id}/feedback` | Thumbs up or down, with a reason for down: `incorrect`, `not_helpful`, `missing_sources`, `wrong_sources`, `outdated`, `harmful_or_unsafe` or `other`. Since v0.4.0, `share: true` with a thumbs down shares the question with the team's [gap report](/docs/using/editors/gaps) (`shared` in the result; `feedbackShared` on conversation messages). |
| `GET /v1/messages/{id}/sources/{n}` | Since v0.4.0: source `n` of an answer, in context (below). |

A personal key reaches only conversations with its own team's agents, within its restrictions.

### Cited passages

`GET /v1/messages/{messageId}/sources/{n}` returns what the [source viewer](/docs/using/source-viewer) shows: a `CitedPassage` with `status` (`available`, `document_deleted` or `passage_changed`), the title, heading path and link, the passages around the cited one (about a page, the cited one marked), the claims of the answer that cite it with this source's verdict, and `documentTeam` when the caller may open the whole document. Only the person who asked can read it (a personal key needs the `query` scope); anyone else, team and platform admins included, gets 404. A tool's result isn't a passage (404).

- An anonymous visitor reads the same for their own session's answers with `GET /v1/public/agents/{agentId}/messages/{messageId}/sources/{n}`, and rates them with `POST /v1/public/agents/{agentId}/messages/{messageId}/feedback` (the same body as above; limited like public questions, on counters of its own).
- The team's editors, admins and owners, and keys with the `ingest` or `manage` scope, read a whole document with `GET /v1/teams/{team}/sources/{sourceId}/documents/{documentId}/text`: `?from=&limit=` (up to 200 passages) or `?around={chunkId}` for a passage in context. Members get 403.

## Searching without an answer

`POST /v1/teams/{team}/kbs/{kbId}/retrieve` returns the passages a knowledge base's hybrid search finds, with citations, and no chat model call. It counts against the team's query limits. See the [reference](/docs/api/reference/kbs/retrieve).

With a platform [rerank model](/docs/administration/reranking) (since v0.4.0), the search is reranked: each hit has `rerankScore`, and the result's `rerank` says how (`status`: `ok`, `timeout`, `error` or `skipped`; `candidates`; `latencyMs`). Send `rerank: false` to compare with the usual order.
