---

Grounded's web app has two portals. The **workspace** is for everyone: the agents you can use, your conversations, and for team members, the team's sources, knowledge bases and agents. The **admin portal** is for platform admins and auditors. People with a platform role switch between them at the top of the sidebar. ⌘K (Ctrl+K) opens a command palette that finds pages, actions and objects by name anywhere in the app.

## Asking a question

Home shows the agents you can use. Open one to chat: it greets you with a welcome message and a few starter questions.

<Screenshot slot="home-agents" />

Answers stream in with numbered citation chips. Each chip opens a card with the passage it refers to; the sources under the answer start collapsed. When the platform has a SystemOne model and citation checks are on for the agent, each factual sentence is a **claim** with a verdict, and the answer carries a one-line summary such as "9 of 10 claims supported · 1 uncited".

<Screenshot slot="chat-answer-with-claims" />

Your conversations are listed in the sidebar and on the Conversations page. Only you can read them. See [Chatting with an agent](/docs/using/chat). Your name at the bottom of the sidebar opens the account menu: **Profile**, **API keys** (if you're in a team), **Notification settings**, **Connected apps**, the **Theme** (System, Light or Dark), **Help** when your organisation has a support page, and **Sign out** (see [Your settings and dark mode](/docs/using/personal-settings)).

## Building for a team

A team's sidebar has **Overview**, **Data sources**, **Knowledge bases**, **Agents**, **Evaluations**, **Gaps**, **Content health** and **Team settings**. Evaluations, Gaps and Content health are for editors, admins and owners only.

<Screenshot slot="team-overview" />

<Steps>
<Step>

### Add a data source

Upload files, or create a web source that crawls part of a site. Grounded parses, splits and indexes each document; a web source re-syncs on a schedule and removes pages that disappear. See [Data sources](/docs/using/editors/data-sources).

</Step>
<Step>

### Create a knowledge base

Attach one or more sources and test search on its **Try it** tab. See [Knowledge bases](/docs/using/editors/knowledge-bases).

</Step>
<Step>

### Build an agent

Start from a blank agent or a template, write instructions, pick a chat model and the knowledge bases, and try the draft in the panel beside the settings. Publish it when it answers well. See [Agents](/docs/using/editors/agents). A [router](/docs/using/editors/routers) is a front-door agent that sends each question to another agent instead.

</Step>
<Step>

### Share it

Keep it for the team, share it with signed-in users, or make it public with a page and an embeddable widget. It is also a model on the OpenAI-compatible API. See [Sharing an agent](/docs/using/editors/sharing).

</Step>
<Step>

### Check it keeps working

Evaluation sets check that the knowledge base still finds the right documents and the agent still answers well after sources, settings or models change. See [Evaluations](/docs/using/editors/evaluations).

</Step>
<Step>

### Find what's missing

**Gaps** groups the questions your agents couldn't answer into topics ([Gaps](/docs/using/editors/gaps)). **Content health**, when a platform admin has turned it on, reports documents not processed in a long time, links a crawl saw fail, the same file in two sources, documents with no retained citation evidence, and documents that failed to parse ([Content health](/docs/using/editors/content-health)).

</Step>
</Steps>

## Running the platform

The admin portal opens on **Overview**: the platform at a glance, what needs attention, the optional features and their state, and the latest changes. **Settings**, under Operations, holds the platform's general settings and the feature switches: Evaluations, Team requests, Webhooks, Content health reports, MCP server, OAuth sign-in for MCP clients and Saved answers. Its sidebar groups the rest: **People**, **Content**, **Models**, **Usage & spend**, **Safety**, **Records** and **Operations**.

<Screenshot slot="admin-overview-features" />

Platform admins can't see team content by default. Auditors see everything the admins see, read-only. See [The admin portal](/docs/administration).
